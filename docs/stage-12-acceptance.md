# Этап 12 — итоговая приёмка базовой версии

Дата: 9 октября 2026 года. **1.9.2 / код 13, Room 7, JSON 6; Android 8.0 (API 26) и выше.** Все 12 этапов базового плана завершены в описанных границах. В проверенных сценариях блокирующих ошибок или потери данных не обнаружено; это не гарантия совместимости с неизвестными файлами или всеми устройствами.

## Итог реализации

- Самостоятельное локальное приложение без внешней идентичности, Telegram, сервера, телеметрии и сетевых разрешений. Автоматический системный бэкап/перенос отключён; копии создаются вручную.
- Универсальная тренировка (дата, спорт, центр, профиль, UUID), отдельные футбольные детали и несколько трасс скалолазания; атомарное создание, исправление и подтверждаемое удаление.
- Футбол: счёт, личные голы/передачи, необязательные дистанция/игроки/минуты. Скалолазание: дисциплина, применимая шкала/категория, результат и повторы; неоднозначная старая категория сохраняется без выдуманной интерпретации.
- Общая и спортивная статистика, единый фильтр периода/центра, месяцы, страницы истории; пропуски необязательных значений не считаются нулями, шкалы не сравниваются между собой.
- Центры с доступными спортами и архивом. Календарь результатов/разовых и еженедельных планов, исключения отмены/переноса, атомарная связь плана с результатом.
- JSON 1–6 и документированный футбольный CSV, предпросмотр/явное сопоставление, UUID и сохранение одинаковых реальных тренировок; транзакционное восстановление и проверка записанной копии чтением.
- Миграции Room 1 → 7 без разрушительного пересоздания, восстановление черновиков, состояния чтения/ошибки/повтора, длинные формы с IME/большим шрифтом и альбомная навигация.
- Совместимый набор зависимостей закреплён на этапе 2; проверка первичных источников — **7 октября**, не новый аудит последних релизов 9 октября. Инструменты и ссылки: [отчёт этапа 2](stage-02-toolchain.md).

## Что добавлено на этапе 12

README приведён к завершённому приложению: сборка, установка/обновление без очистки, подпись, тесты, архитектура и ограничения. Русская и английская инструкции сверены и дополнены одинаковыми правилами обновления, быстрым стартом и безопасным использованием примеров. Описание бэкапа и справочника согласовано с JSON 6; ссылки/даты первичных источников шкал сохранены в [справочнике](climbing-grades.md).

Публичные [примеры](examples/README.md) без персональных данных: JSON 6 с 3 результатами, разными дисциплинами, связанным/отменённым/перенесённым планами и серией; CSV с заполненными и пустыми необязательными полями. `DocumentedExamplesTest` читает **сами файлы документации** через androidTest assets, проверяет значения/связи и отсутствие дублей. Основной APK эти assets не получает.

`SportModuleRegistry` выделен для проверки расширения: собственный снимок списка, защита пустого/повторного slug. Три JVM-теста используют отдельный третий `contract_probe`, не меняя рабочий реестр из футбола/скалолазания. Это ограниченная проверка валидатора/декодера/метрик и регистрации, не реализация третьего спорта. Реальному модулю нужны свои DTO, таблица/миграция, версия обмена, SQL и редактор: [инструкция](sport-modules.md). Проверка ZIP/Dex итогового debug APK подтвердила отсутствие пробы, её тестового класса и примеров CSV/JSON.

## Финальный автоматический прогон 1.9.2

Среда та же, что в [этапе 11](stage-11-local-testing.md): Windows, JBR 25.0.3, compile SDK 37.1 / target 37 / min 26; изолированный API 26 x86_64 и read-only API 37 x86_64 с 16-КиБ страницами, 4 vCPU / 2048 МиБ каждый. Wi-Fi и мобильные данные перед/после прогонов: `wifi_on=0`, `mobile_data=0`. Пользовательские установки и реальные базы не использовались.

```powershell
$env:JAVA_HOME='C:\Program Files\Android\Android Studio\jbr'
# Только отдельные пустые тестовые AVD; serial сверить через adb devices:
.\scripts\run-local-checks.ps1 -Serial emulator-5556 -SdkPath 'C:\Users\PAVEL\AppData\Local\Android\Sdk' -ExpectedAndroidTests 123
.\scripts\run-local-checks.ps1 -Serial emulator-5554 -SdkPath 'C:\Users\PAVEL\AppData\Local\Android\Sdk' -ExpectedAndroidTests 123
```

Скрипт проверяет пустую установку и запускает `--offline verifyOfflinePolicy testDebugUnitTest lintDebug assembleDebug assembleRelease connectedDebugAndroidTest`. Отчёт обязан быть свежим и содержать ожидаемое число тестов; один `BUILD SUCCESSFUL` не принимается. Не запускайте runner на устройстве с личной историей.

## Заключительные ручные проверки 1.9.2

После runner установлен именно итоговый debug APK на два пустых тестовых AVD; проверены `versionName=1.9.2`, `versionCode=13`, запуск и 0 результатов. На API 37 через системный `OpenDocument` выбран `training-backup-v6.json`, применены 3 результата / 4 плана / 1 серия. Общий экран показывает 2 футбольные тренировки, 1 личный гол/передачу и 2 из 5 успешных попыток скалолазания; снимок `.local-testing/stage12-api37-statistics.png` визуально просмотрен.

Через `CreateDocument` создан отдельный `stage12-verified.json`, получено «Копия сохранена и проверена чтением файла». Фактический файл 9993 байта скопирован в `.local-testing/stage12-verified.json`: JSON 6, 3 результата, 4 трассы, 4 плана, 1 серия и UUID связанного результата совпадают с примером. После холодного перезапуска API 37 история сохранилась. Этот фактический бэкап выбран через `OpenDocument` и восстановлен в чистую 1.9.2 на API 26: 3 результата / 4 плана / 1 серия. Повторный выбор/применение того же файла на API 26: 0 результатов добавлено, 3 пропущено; 0 новых планов/серий/центров/избранных. Синтетические копии не являются данными пользователя; исходный AVD всё ещё read-only.

## Артефакты, ограничения и фиксация

Устанавливаемая debug-сборка: `app/build/outputs/apk/debug/app-debug.apk`, 24538038 байт, SHA256:

```text
a13c43bcb9078d62a9dcd327877f46170d37efbbf5e6cb78e0153c101e062344
```

Release: `app/build/outputs/apk/release/app-release-unsigned.apk`, 17315334 байта. Он **неподписанный**, не устанавливался и не публиковался. Хэш относится к проверенному локальному debug-файлу, не к любому будущему пересобранному APK. APK/SDK/AVD, локальная база и контрольные копии не коммитятся.

Границы базовой версии: реальные исторические файлы не предоставлены, поэтому неизвестные выгрузки и CSV скалолазания не обещаются; для их адаптера нужен обезличенный образец. Физическое устройство и полный аудит жестов/слышимого TalkBack не проверены. Не реализованы третьи спорты, дополнительные шкалы/подтверждение старой категории, время скорости, графики, уведомления и переключение профилей. Есть неблокирующая языковая полировка: некоторые счётчики используют фиксированную форму слова, например «1 тренировок». Английское руководство не означает английскую локализацию. Внешние предупреждения Gradle/Protobuf из этапа 11 сохраняются; ошибок Lint нет. Публикация в магазин и создание ключа распространения не выполнялись.

Этапы 10.2 и 11 отправлены отдельными коммитами `0ec5ffe` и `de82947`; этот этап фиксируется отдельно. Готовое сообщение: `Этап 12: завершить документацию и приёмку локального приложения`. Обычный push — только в согласованный `origin/main` (`git@github.com:PavelMurlykin/sports_activity_assistant.git`), без force; итоговый SHA сверяется с удалённой веткой после отправки.
