# Локальный обмен данными: JSON 5 и старые форматы

Обмен UUID введён в JSON 4 на этапе 5; JSON 5 добавляет состояние архива центров на этапе 6 (8 октября 2026 года). Версия JSON независима от схемы Room: приложение 1.5.0 хранит Room 6 и экспортирует JSON 5. Файл — обычный незашифрованный UTF-8 JSON. Числовое поле `schemaVersion` обязательно; неизвестные версии и поля отклоняются до записи. Лимиты импорта и экспорта: 16 МиБ и 100000 объектов суммарно, включая справочники, трассы, профили, планы, серии, избранное и сопоставления.

## Состав JSON 5

`exportedAt` — время снимка UTC. `sports` содержит поддерживаемые `slug` и названия (`football`, `climbing`); общая статистика расширяется через зарегистрированные спортивные модули, а не неизвестные значения файла.

| Массив | Идентичность и связи |
| --- | --- |
| `profiles` | `publicId` (UUID), необязательное локальное `displayName`, `createdAt`; `primaryProfilePublicId` определяет основной профиль |
| `centers` | `publicId`, `createdAt`, `name`, необязательный `city`, `sportSlugs`, булевый `isArchived` (по умолчанию `false`); числовой `legacyId` только справочный |
| `trainings` | `publicId`, `createdAt`, `date`, `sportSlug`, `centerPublicId`, `profilePublicId`; спортивные данные — дочерний объект `football` или массив `climbingRoutes` |
| `climbingRoutes` | Собственный `publicId`, дисциплина, исходная категория, шкала/код, результат, историческое число повторов, тип трассы скорости и метаданные неизвестной дисциплины |
| `recurrenceRules` | `publicId`, `createdAt`, ссылки на профиль/центр/спорт, даты начала/окончания, `frequency` (`weekly`/`none`), положительный `intervalWeeks` |
| `plannedTrainings` | `publicId`, `createdAt`, ссылки на профиль/центр/спорт, дата, `status` (`planned`/`canceled`), необязательный `recurrenceRulePublicId` |
| `favorites` | Ссылки `profilePublicId`, `centerPublicId`, `createdAt` |
| `aliases` | `kind` (`center`/`profile`), `sourceKey`, `targetPublicId`; ранее подтверждённые сопоставления для повторного импорта |

UUID имеют каноническую строчную форму, не зависят от локальных числовых ключей Room и не повторяются между объектами файла. `createdAt` обязателен у сущностей JSON 4/5; поддерживается точность до миллисекунд. Даты тренировок — строго `YYYY-MM-DD`, годы 0001–9999. Отсутствующий родитель, неизвестный статус/частота, ошибочная категория/шкала, смешанные спортивные данные и недопустимые числа — ошибки, а не повод подставить значение по умолчанию. Имена центров внутри тренировок/планов — отображаемые сведения; связь определяется UUID. Локальные числовые `legacyId` не используются как идентичность JSON 4/5.

JSON 5 переносит активные и архивные центры вместе с их историями, планами, сериями и избранным. JSON 1–4 не принимают поле `isArchived` и адаптируются с `false` для новых центров. Локальное состояние центра при объединении сохраняется; старая копия не открывает закрытый центр. Для одного UUID различие архива в JSON 5 — явный конфликт, в JSON 4 отсутствующее состояние не считается конфликтом. Планы и серии архивирование не отменяет.

Полный синтетический пример предыдущего JSON 4, проверяемый Android-тестом: `app/src/androidTest/assets/exchange-backup-v4.json`. Модели формата находятся в `data/backup/BackupModels.kt`.

## Объединение и конфликт UUID

Предпросмотр ничего не записывает. При применении весь файл повторно проверяется в транзакции Room. Ошибка, включая отказ после начала вставок, откатывает профили, центры, историю, планы, избранное и сопоставления вместе. База никогда не очищается импортом.

- Одинаковый UUID и данные: запись уже существует, повторной вставки нет.
- Одинаковый UUID, разные данные: нужно явно подтвердить «Сохранить локальную запись». Автоматической перезаписи нет. Это относится и к планам, сериям, центрам и метаданным профиля.
- Разные UUID, одинаковое содержание: сохраняются обе тренировки. Совпадение показано как предположение; можно явно пропустить запись из файла. Это решение не записывает постоянный запрет: при следующем импорте пропуск следует подтвердить снова.
- При сопоставлении двух разных центров сохраняются метаданные, состояние архива и текущие виды спорта центра назначения. Идентичность источника сохраняется в `aliases`; последующее изменение сопоставления блокируется.
- Неиспользованные начальные центры чистой установки могут принять UUID, дату создания и свойства центра из копии. Центры старой базы не считаются «начальными» по имени: миграция 4 → 5 выставляет флаг `is_initial = false`. Реальные пользовательские центры не перезаписываются.
- Пустой начальный профиль без истории/избранного/сопоставлений принимает идентичность выбранного основного профиля. В заполненной базе выбранная личная история объединяется с текущим профилем через явное сопоставление.
- При нескольких профилях необходимо выбрать один или «Сохранить все отдельно». В последнем случае основной профиль соответствует текущей личной статистике, остальные сохраняются отдельно и входят в следующий бэкап; переключения профилей в интерфейсе пока нет. Статистика и календарь не смешивают их результаты.
- Если разные профили уже были явно объединены с одной личной историей предыдущими импортами, приложение не утверждает, что может разделить их автоматически: режим «все отдельно» блокируется для такого сопоставления.

Восстановление истории не требует, чтобы центр по-прежнему предлагал прошлый вид спорта: исторические ссылки сохраняются. У исторического центра может быть пустой список текущих видов спорта. Создание новой тренировки/плана требует активного центра и доступности выбранного спорта в нём. Названия поддерживаемых видов спорта берутся из локального справочника приложения; импорт не меняет его пользовательские названия.

## Сопоставление похожих центров

Общий ключ — Unicode NFC, удаление/свёртывание пробелов (включая неразрывные), строчный регистр Locale.ROOT. Отсутствующий, пустой и пробельный город имеют один ключ. Ручное создание и переименование не добавляют нормализованные дубли, включая архив; проверки выполняются в транзакции. Миграция 5 → 6 добавляет только `is_archived = false`, не меняя прежние имена, UUID, даты и ссылки. Неизменённые исторические дубли можно редактировать/архивировать без объединения.

JSON 4/5 сохраняет похожие исторические центры по разным UUID с предупреждением, если имя неоднозначно. Новая запись с ненулевым `city` и уже занятым точным `(name, city)` требует сопоставления из-за старого уникального индекса SQLite. Для JSON 1–3/CSV нормализованный дубль требует явного сопоставления. Имена при восстановлении не переписываются нормализатором.

## Адаптеры JSON 1–3 и футбольного CSV

JSON 1/2 адаптируются с сохранением исходных обозначений трасс; только однозначная старая трудность распознаётся как французская. JSON 3 уже содержит метаданные шкал. Все версии сохраняют несколько трасс внутри одной тренировки. Старые JSON не содержали владельцев, UUID, даты создания и связь плана с серией: эти сведения не угадываются. Создаётся один профиль без сведений об исходном владельце, новые даты создания назначаются при импорте. Отсутствующие старые связи нельзя восстановить.

Для старых файлов без UUID идентификатор выводится из SHA-256 точных байтов файла, типа объекта и его позиции. Две одинаковые строки сохраняют разные UUID, повторный импорт неизменённого файла — те же UUID. Даже изменение пробелов, кодировки или переносов строк меняет идентичность источника; проверьте предложенные совпадения и храните оригинал.

CSV предназначен только для футбола. Требуются `user_id`, `training_date`, `sports_complex_id`, `team_goals_scored`, `team_goals_conceded`, `user_goals_scored`, `user_assists`. Необязательные колонки: `distance_km`, `players_per_team`, `duration_minutes`. Пустое необязательное значение — `null`, не ноль. Поддерживаются `;`/`,`, десятичная запятая (в CSV с запятыми — в кавычках), UTF-8/BOM, Windows-1251, удвоенные кавычки и переносы строк внутри кавычек. Ошибки CSV указывают физическую строку и поле; разбор JSON не переключает повреждённый UTF-8 на другую кодировку.

`user_id` — только поле файла, не внешний аккаунт. Числовой ID центра — лишь подсказка: для CSV необходимо подтвердить существующий центр или создание исторического центра. Это не соединение с каким-либо сервисом.

Образец фактической многолетней истории не предоставлен. Произвольные CSV скалолазания/табличные выгрузки не поддерживаются и не считаются проверенными; для нового адаптера нужен обезличенный файл. Действующие адаптеры скалолазания — документированные JSON 1–5. При добавлении в этапе 8 исключений серий и связи плана с результатом формат и миграционные тесты нужно расширить одновременно с сущностями.

## Системный диалог и проверка копии

Экспорт сначала делает согласованный снимок базы, затем открывает `CreateDocument`. После закрытия записанного файла приложение читает его обратно и сравнивает точные байты. Только эта проверка даёт сообщение об успешном сохранении. Ошибка доступа/записи/чтения сообщает, что файл может быть неполным; не используйте его вместо предыдущей проверенной копии. Отмена диалога не показывает успех. Импорт использует `OpenDocument`, ограниченное чтение, фоновый разбор и явное подтверждение; широкие разрешения на хранилище не нужны.

Одна файловая операция блокирует следующую, включая открытый диалог и предпросмотр. Состояние хранится в ViewModel при повороте; закрытие процесса требует начать операцию заново. Не подтверждайте копию после прерывания процесса: выбранный файл может остаться пустым. Выбирайте локальное хранилище устройства; облачные пункты системного диалога предоставляются сторонними приложениями, не этой программой.
