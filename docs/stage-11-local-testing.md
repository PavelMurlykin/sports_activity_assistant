# Этап 11 — сквозная локальная проверка

Проверки выполнены 9 октября 2026 года. Приложение 1.9.1 / код 12, Room 7, JSON 6. Исправлен найденный при приёмке дефект сообщения повреждённого JSON; схема и формат не менялись.

## Предварительные условия и пороги

Пороги зафиксированы **до первого замера**. Синтетическая личная история: 2000 тренировок за 2016–2025 годы (1000 футбольных, 1000 скалолазных), по 10 строк трасс в скалолазной тренировке, 4 центра. Это примерно 4 тренировки в неделю за 10 лет. Реальные файлы пользователя не предоставлены.

На локальном x86_64 AVD с 4 виртуальными ядрами и 2048 МиБ RAM:

| Операция | Максимум |
| --- | --- |
| JSON: разбор, предпросмотр, применение в пустую базу | 30 с |
| Повторный импорт того же файла без дублей | 30 с |
| Создание JSON-бэкапа | 15 с |
| Запрос обзора, итогов одного спорта, страницы истории или месяца календаря (каждый) | 2 с |
| Открытие экрана из навигации до отображения контрольного текста на заполненной базе | 5 с |

Времена запросов не являются измерением FPS или времени отрисовки. Измерения инструментальные, debug APK, первое обращение к API чтения без отдельного прогрева; страницы SQLite/файлового кэша уже могли читаться во время импорта. Это приёмочные пороги на указанной машине, не гарантия для всех устройств. Копия восстанавливается в отдельную чистую файловую Room-базу; сравниваются UUID, детали и количества, повторный импорт не должен создавать записи. Тестовые базы удаляются только по своим точным именам.

## Изолированная среда

API 26 образ берётся из [официального каталога Android SDK](https://dl.google.com/android/repository/sys-img/google_apis/sys-img2-1.xml). `scripts/prepare-api26.ps1` проверяет контрольную сумму архива; новую лицензию автоматически не принимает. Образ и AVD находятся в игнорируемой `.local-testing/api26`, существующие AVD не изменяются. Для выбора отдельного каталога используется [ANDROID_AVD_HOME](https://developer.android.com/tools/variables).

API 37.1: существующий `Medium_Phone` запускается с `-read-only -no-snapshot-save`, поэтому пользовательский AVD не перезаписывается. Физическое устройство пока не подключено. Сценарии выполняются с выключенными Wi-Fi и мобильными данными; сетевые разрешения и автоматический бэкап проверяются отдельно.

Хост: Windows 10.0.28000, Intel Core Ultra 7 255HX (20 ядер), около 32 ГиБ RAM; WHPX, SwiftShader. JDK Android Studio 25.0.3; Emulator 37.2.12; compile SDK 37.1 / target 37 / min 26. Версии библиотек остаются закреплёнными набором этапа 2, проверенным 7 октября, а не объявляются повторно «новейшими».

- API 26: Android 8.0.0, Google APIs x86_64 revision 16; 720×1280 / 240 dpi, 4 ядра, 2048 МиБ. Архив `x86_64-26_r16.zip`, 980740438 байт, SHA1 `0eb13cc91cf164b617eaf85e4030289cb18189de`.
- API 37: Android 17, Google APIs Play Store x86_64 / 16-КиБ страницы; 1080×2400 / 420 dpi, 4 ядра, 2048 МиБ.

Для отдельного API 26 создавались `.local-testing/api26/avd/Acceptance_API26.ini` с абсолютным `path` к `Acceptance_API26.avd` и `target=android-26`, а внутри AVD — `config.ini`: `abi.type=x86_64`, `hw.cpu.arch=x86_64`, `hw.cpu.ncore=4`, `hw.ramSize=2048`, `hw.gpu.enabled=yes`, `hw.gpu.mode=swiftshader`, параметры экрана выше, `hw.keyboard=yes`, `disk.dataPartition.size=2G`, `image.sysdir.1` — абсолютный путь к распакованному `image/x86_64`, `tag.id=google_apis`, `target=android-26`. Имена/пути относятся к тестовой среде, не к пользовательской установке.

```powershell

Перед тестами проверены `wifi_on=0`, `mobile_data=0`; на API 26 Wi-Fi отключён штатным UI «Network & Internet» и `dumpsys wifi` подтвердил `Wi-Fi is disabled`. Защищённый broadcast airplane mode недоступен shell на API 26: привилегии не повышались, он не используется в инструкции. Один только флаг авиарежима не доказывает отключение Wi-Fi.

## Ручные сценарии

1. На обоих AVD установлена точная предыдущая 1.8.1 из коммита `2ec4668`, собранная отдельно через `git archive` без замены рабочего дерева. Первый запуск без демонстрационной истории; файл `exchange-backup-v4.json` выбран из локальной Downloads через системный диалог, применены 2 тренировки / 2 трассы / 1 план / 1 серия.
2. JSON 6 сохранён через системный `CreateDocument`; приложение подтвердило чтение. Установка 1.9.0 выполнена через `adb install -r`, **без очистки базы**. Снимки до/после на каждом AVD совпали полностью, исключая `exportedAt`. Затем обе установки обновлены с `-r` до 1.9.1: в UI сохранились 2 тренировки, оба спорта и 1 из 2 успешных попыток. Холодный запуск сохраняет историю.
3. После тестового runner выполнена чистая установка API 26 и восстановление сохранённого JSON 6 через `OpenDocument`. Предпросмотр сохранился при настоящем повороте 0 → 1 → 0. Повторное применение: 0 добавленных, 2 пропущенных тренировок; планы/серии не дублируются.
4. JSON 999 отклонён с русским сообщением. Повреждённый JSON отклонён; после исправления в 1.9.1 сообщение предлагает проверенную копию и не раскрывает фрагмент файла. Общая статистика после ошибок по-прежнему 2. Отмена системного экспорта и выбора импорта не показывает успех; первый Back при открытой IME скрывает клавиатуру, второй закрывает файловый диалог.
5. Визуально проверен экран восстановленной статистики 1.9.1 на API 26, снимок `.local-testing/stage11-api26-statistics.png`. Детальные сценарии ввода/календаря/IME и системного восстановления процесса из предыдущих этапов не выдаются за новый ручной прогон всех комбинаций: они дополнены полным текущим автоматическим прогоном на двух API.

Удалялись только собственные синтетические установки приложения на тестовых AVD для повторного запуска runner; их контрольные копии сохранены и восстанавливаются. Исходный пользовательский AVD запущен read-only, реальные данные пользователя не предоставлены и не изменялись.

## Найденные проблемы и исправления

- Повреждённый/неподдерживаемый JSON выдавал английскую ошибку Serialization с содержимым файла. `ImportParser` теперь заменяет её ресурсным объяснением; исходная причина не используется как UI-текст. Неверный корень/тип `schemaVersion` проверяются явно. Добавлены 2 JVM-теста, включая отсутствие приватного фрагмента в сообщении.
- AGP test runner попытался установить APK поверх ручной установки без `-r`, затем сообщил `BUILD SUCCESSFUL`, хотя тесты не выполнились. Такой запуск **не принят**. Добавлен безопасный preflight и обязательная проверка свежего XML; повторные полные прогоны выше прошли.
- У загрузки образа был разрыв соединения: архив продолжен с того же официального URL и проверен SHA1. Неполный файл не использовался.
- Ошибки селекторов/аргумента PowerShell при подготовке новых тестов устранены; они не считаются дефектами приложения. Локальная UI-оснастка теперь отказывается использовать старый XML, если свежий dump недоступен.

Остаются внешние предупреждения Gradle Configuration.setVisible и Protobuf sun.misc.Unsafe; проверку не блокируют. Физическое устройство, жесты/слышимое озвучивание TalkBack и реальные исторические файлы не проверены. Приёмка касается документированных форматов и двух эмуляторов, не всех Android-устройств.
