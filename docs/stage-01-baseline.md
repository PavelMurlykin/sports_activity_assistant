# Этап 1: самостоятельное офлайн-приложение и исходное состояние

Дата: 7 октября 2026 года. Исходный коммит: `fd6e233a1da3c1acfc974ef3d1481a444d97923d`.

## Неподвижные требования

- Приложение полностью локальное: без внешней авторизации, серверов, сетевых клиентов, аналитики и сетевых разрешений в итоговом APK.
- Единственный локальный профиль не представляет внешний аккаунт. Поле `user_id` старого CSV — информация файла, а не способ входа.
- Резервное копирование только вручную в выбранный файл; автоматический системный бэкап и перенос данных отключаются.
- Системный файловый диалог может показывать сторонние провайдеры. Для офлайн-работы пользователь выбирает локальное хранилище; приложение не должно самостоятельно обращаться к провайдеру без выбранного файла.
- Сеть среды разработки нужна для загрузки недостающих библиотек и `git push`, но не установленному приложению.

## Правила модели для дальнейших этапов

- Общие обязательные поля: дата, спорт и центр. Две тренировки одного спорта в одном центре в один день допустимы, даже если их показатели совпадают.
- Спортивные детали принадлежат ровно одной тренировке и соответствуют её спорту; сохранение атомарное.
- Футбол: четыре обязательных неотрицательных показателя счёта/личного участия. Пустые дистанция, игроки и длительность — `null`, не ноль; дистанция неотрицательна, игроки и длительность положительны, если указаны.
- Скалолазание: одна тренировка содержит несколько записей трасс. В новой записи результат относится к одной трассе/прохождению. Исторический `repeatCount` нужно сохранять без превращения повторов в отдельные тренировки; его точное соответствие исходным файлам ещё требует проверки.
- Нельзя сравнивать сложность разных шкал; применимость категории для скорости определяется на этапе проверки первичных источников.
- План сам по себе не является состоявшейся тренировкой и не влияет на спортивные показатели.
- Ошибочный импорт не должен оставлять частичные данные. Идентификаторы обмена не должны зависеть от внутреннего номера строки базы.

Правила выше — спецификация следующих этапов, не утверждение об их полной реализации в текущем коде.

## Данные и контрольный пример

Пользовательские базы и исходные многолетние файлы не предоставлены. Они не изменялись и не выгружались. Тесты репозитория используют базы в памяти; запуск приложения проверяется в временной read-only сессии эмулятора. Перед будущей миграцией реальной базы требуется ручной бэкап и проверка восстановления на отдельной копии.

Синтетический контрольный файл `app/src/androidTest/assets/control-backup-v2.json` не содержит персональных данных. Ожидаемые значения после импорта в пустую историю:

| Показатель | Ожидается |
| --- | --- |
| Все тренировки | 3; футбол — 2, скалолазание — 1 |
| Футбол: исходы | 1 победа, 1 ничья, 0 поражений |
| Футбол: общий счёт / личные голы / передачи | 2:1 / 1 / 1 |
| Футбол: дистанция / длительность | 4 км учтено; 40 мин в среднем по одной заполненной записи |
| Скалолазание | 3 прохождения, 2 успешных, текущий округлённый процент 66%, максимум 6A+ |
| Календарь | 1 разовый план 15 октября; серия 7, 14, 21 октября; планы не увеличивают статистику |

Перед совместимостью с реальными файлами нужны обезличенные образцы обоих видов спорта и пояснение группировки трасс/повторов. Пока проверяется только описанный формат на синтетических данных; неизвестные форматы не считаются поддержанными.

## Известные риски следующих этапов

База пока сохраняет старый столбец внешнего идентификатора для совместимости схемы. Это не интеграция и не сетевое подключение; удаление столбца выполняется через миграцию на этапе 3. Дедупликация по содержимому, неполные связи бэкапа, общая шкала сложности и отдельное создание плана/результата остаются явными ограничениями. Необходимо устранить их до приёмки базовой версии.

Для политики резервного копирования использована [официальная документация Android Auto Backup](https://developer.android.com/identity/data/autobackup): кроме `allowBackup=false`, нужны правила исключения для новых механизмов переноса. Правила проверяются инструментальным тестом; ручной JSON-экспорт от этих правил не зависит.
