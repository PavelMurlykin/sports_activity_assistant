# Этап 9 — фильтры и расширенная статистика

Дата: 9 октября 2026 года. Приложение 1.8.0 / versionCode 9. Room 7 и JSON 6 не меняются; старые схемы не переписаны, миграция не требуется. Новых библиотек и сетевых разрешений нет.

## Реализовано

- Один включительный фильтр периода и центра для обзора, спортивных итогов и списка результатов: всё время, этот месяц/год или произвольные даты 0001–9999; все центры либо один, включая архивный.
- Применённый фильтр сохраняется через SavedStateHandle, черновик формы — через rememberSaveable. Отмена не применяет изменения; сброс возвращает всё время / все центры.
- SQL-предикаты ограничивают текущий локальный профиль, даты, центр и при необходимости спорт до чтения деталей. Планы/отмены в агрегаты результатов не входят. Все виды спорта остаются в обзоре даже при нулевой выборке.
- Общее число результатов, распределение по спорту, месяцы от новых к старым с нулевыми промежутками. Для явного периода показываются все его месяцы, включая пустую базу; для всего времени — диапазон первой/последней найденной тренировки. Пустые карточки вычисляются по индексу, не создаются заранее для всех 119988 месяцев допустимого диапазона.
- Футбол: игры, W/D/L, командные и личные показатели, сумма/средняя дистанция, сумма/среднее время, средний состав. Для каждого необязательного поля показано число заполненных игр. Null не входит в среднее; 0 км входит. При отсутствии значений — «Нет данных». Суммы целых показателей — Long, средние округлены до двух знаков HALF_UP.
- Дистанция хранится/суммируется точно как BigDecimal: SQL читает только id/дистанцию порциями по 512 с курсором id; преобразования в REAL нет. Проверка точности теперь учитывает числовое значение после удаления конечных нулей, а не различие plain/экспоненциальной формы. Допустимый большой результат после сохранения в Room остаётся допустимым для бэкапа/импорта. Повтор запроса с тем же UUID сравнивает дистанции по значению; чрезмерный порядок отклоняется.
- Скалолазание: тренировки, отдельное число записей трасс, попытки с повторами, успешность; успешно/попытки по дисциплинам, подтверждённым категориям и трассам скорости. Независимые максимумы успешных French / Fontainebleau по рангу справочника, не по строковой сортировке. Исторические неопределённые категории входят в общий/отдельный счётчик, не в подтверждённые максимумы. SQL и каталог одинаково учитывают Unicode-пробелы у категории.
- История: 20 тренировок со связанными деталями на страницу, date DESC / id DESC. Count и страница читаются в одной транзакции. Удаление последнего элемента корректирует номер страницы; страницы перестраиваются при изменении Room, не дописываются к старой выдаче. Итоги относятся ко всей выборке. Смена фильтра отменяет прежний Flow и возвращает первую страницу.
- Обзор и спорт используют отдельные агрегаты вместо полной истории TrainingBundle. Календарь также больше не загружает всю историю результатов для сигнала изменения: invalidation tracker запускает чтение видимого диапазона. Полный снимок остаётся только операциям обмена.

Обновлены обе пользовательские инструкции, README, план, контракт спортивных модулей и описание числовых ограничений формата обмена.

## Контрольные расчёты

1. Футбол, три выбранные игры: дистанции null / 0 / 0.3 → сумма 0.3 км, среднее 0.15 км, 2 из 3; минуты null / 40 / 41 → сумма 81 мин, среднее 40.5 мин, 2 из 3. Показатели W/D/L — 1/1/1. Чужой профиль, другой центр и запись вне диапазона исключены. Архивирование выбранного центра не удаляет его историю.
2. Скалолазание, две тренировки: 5 строк / 12 попыток / 10 успешных → 83%; трудность 3/5, болдер 5/5. Успешный максимум трудности 6b+, неудачная 9c остаётся в распределении 0/2; болдер — 7A. Четыре исторические попытки не повышают максимум.
3. Пагинация: 61 запись одной даты → страницы 20/20/20/1 с устойчивыми ID. После удаления последней записи последняя страница пересчитывается; изменение только футбольных деталей обновляет агрегат.
4. Синтетическая база из 5000 футбольных записей: сумма личных голов 10737418235000 без Int-overflow. Для 513 дистанций по 10²¹ км — точная сумма 513000000000000000000000 км. Проверены порции 512, ограниченный запрос истории и использование существующего индекса user_id/training_date без временной сортировки. Это тест SQL/арифметики, не замер импорта реальной истории.
5. Контрольный JSON 2 даёт те же метрики через SQL и независимый расчёт по малому набору в памяти. Проверены пустая выборка, одна запись, нулевые результаты, границы високосного месяца/года, многолетние промежутки, отсутствие пропусков месяцев и отдельное сохранение будущего импортированного результата.
6. Compose/VM: строгие даты, отказ от обратного диапазона, отмена/сброс, архивный центр, восстановление черновика и применённого выбора, быстрые переключения, общий фильтр обзора/спорта, реальное переключение страниц и возврат к обзору.
7. Допустимая экспоненциальная дистанция проверена после plain TEXT в Room, повторного ручного запроса и повторного импорта собственного JSON без дублей.

## Ограничения и следующий этап

Фильтры пока ограничены периодом и одним центром; графиков и одновременного сравнения нескольких центров нет. Подтверждение исторических шкал не реализовано. Страницы ограничивают родительские тренировки; детали одной тренировки пока читаются целиком. Фильтры/черновики не входят в JSON.

API 26, физическое устройство, TalkBack, увеличенный шрифт и измерение импорта многолетней истории не объявляются проверенными. Синтетический SQL-набор не заменяет эти сценарии этапов 10–11. Настоящая история не предоставлена. Release APK не подписан ключом распространения; удалённый CI не наблюдался.

Следующий этап — состояния интерфейса, lifecycle-aware наблюдение, доступность и строковые ресурсы (этап 10).
