# Этап 6: спортивные центры и архив

Проверено 8 октября 2026 года. Приложение 1.5.0 (`versionCode = 6`), Room 6, экспорт JSON 5, импорт JSON 1–5 и документированного футбольного CSV. Этап выполнен без сетевой зависимости приложения.

## Реализовано

- Создание и редактирование центра с одним/несколькими видами спорта. UUID, локальный ключ и исходная дата создания сохраняются; ошибка оставляет форму открытой с введёнными данными, двойное сохранение блокируется.
- Общая нормализация названия/города: Unicode NFC, свёртывание пробелов, включая неразрывные, и сравнение без регистра через Locale.ROOT. Пустой/отсутствующий город имеют один ключ. Поля ограничены 200 символами каждое.
- Новые ручные дубли и переименование в занятое сочетание запрещены, включая архивные центры. Разные города разрешены. Исторические похожие центры не объединяются; неизменённые имена позволяют редактировать предложения или архивировать.
- Вкладки «Активные»/«Архив», подтверждение архивирования и возврата. Нет удаления центра, результатов, избранного, планов или серий. Архивирование не отменяет прежние события.
- Обе формы тренировок используют живой справочник вместо независимых асинхронных запросов. После смены спорта/предложений несовместимый центр сбрасывается; выбирается первый доступный либо показаны объяснение и создание центра с текущим спортом.
- Проверка активного центра и предлагаемого спорта повторяется внутри транзакции сохранения, поэтому устаревшая форма не обходит ограничение.
- Прокрутка формы, перенос длинного названия и FlowRow для множества видов спорта; в редакторе справочника поля центра и выбранные виды спорта сохраняются при повороте.
- Миграция 5 → 6 добавляет `is_archived = false`, не меняя исторические имена/UUID/даты/ссылки. Замороженные схемы 2–5 не изменены, добавлена 6.json.
- JSON 5 переносит архив вместе с историей и связями. Старые JSON 1–4 не принимают новое поле; их новые центры активны. Объединение не открывает локальный архив и не меняет текущие предложения. Конфликт архива одного UUID в JSON 5 требует подтверждения сохранения локальной записи.
- Неоднозначные похожие центры JSON 4/5 восстанавливаются отдельно по UUID с предупреждением; точный конфликт ненулевого `(name, city)` старого индекса требует сопоставления. Нормализация не переписывает импортированную историю.

## Ручные сценарии

На эмуляторе без сети создан синтетический Stage06 Arena без города, с футболом и скалолазанием. После поворота в альбомную ориентацию и обратно название и оба выбранных спорта сохранены. Через календарь записаны футбольный результат 0:0 с пустыми необязательными полями и разовый план.

Проверены отмена и подтверждение архивирования, вкладка архива и возврат центра в активные. Архивный центр отсутствует в списке новых планов, но прежний результат и план видны в календаре; статистика сохраняет 1 тренировку. Удаление футбола из текущих предложений сохраняет прежние футбольные записи. Центр снова архивирован.

Через системный CreateDocument сохранён и проверен обратным чтением реальный файл JSON 5: архивный центр с текущим скалолазанием, прежние футбольные результат и план. Через OpenDocument повторный импорт добавил 0 тренировок/планов/серий/центров, 1 тренировку пропустил. Холодный запуск сохранил архив. После последнего Android-прогона эта реально сохранённая копия восстановлена через OpenDocument в чистую установку: 1 результат, 1 план и 1 пользовательский архивный центр.

Локальные снимки/файлы находятся в игнорируемой `.local-testing/`; это синтетические данные тестового эмулятора, не история пользователя.
