# Sports Activity Assistant

Локальное Android-приложение на Kotlin и Jetpack Compose для учёта личных тренировок. Проект переносит предметную модель из [`sports_activity_bot`](https://github.com/PavelMurlykin/sports_activity_bot) и не требует сервера.

## Возможности

- универсальная запись тренировки: дата, вид спорта и спортивный центр;
- отдельная статистика каждого вида спорта;
- футбол: счёт, личные голы и передачи, необязательные дистанция, число игроков в команде и длительность;
- скалолазание: несколько трасс за тренировку, дисциплины «Трудность», «Скорость» и «Боулдеринг», французская шкала сложности от `3` до `9C`, признак успешного прохождения каждой трассы;
- общая статистика, группировка по месяцам и детальные агрегаты по спорту;
- календарь состоявшихся, разовых будущих и еженедельных тренировок;
- редактируемый справочник спортивных центров и доступных в них видов спорта;
- импорт исторического CSV Telegram-бота;
- локальный экспорт и повторный импорт полной резервной копии JSON;
- защита от повторного импорта одинаковых тренировок.

При первом запуске создаются только справочники и локальный профиль; демонстрационные тренировки используются исключительно в тестах и не попадают в пользовательскую статистику.

Базовая таблица `trainings` не содержит специфичных для спорта полей. Футбольные данные лежат в `football_trainings`, скалолазные — в `climbing_trainings` и `climbing_routes`. Поэтому новый вид спорта добавляется отдельной дочерней сущностью, формой и расчётом статистики без изменения общих атрибутов календаря.

## Импорт CSV из Telegram-бота

Приложение принимает UTF-8/UTF-8 BOM и Windows-1251, разделители `;` и `,`. Заголовок совместим со скриптом исходного бота:

```csv
user_id;training_date;sports_complex_id;team_goals_scored;team_goals_conceded;user_goals_scored;user_assists;distance_km
1000001;2025-12-14;2;5;3;2;1;7,35
1000001;2025-12-21;2;1;1;0;1;
```

`sports_complex_id` должен существовать в справочнике приложения. Начальные идентификаторы совпадают с ботом: `1` — «Энергия Высоты», `2` — «Фабрика Футбола», `3` — «Арена на горе». Поле `user_id` читается для совместимости, но данные импортируются в локальный профиль приложения. Совпадающие записи пропускаются.

## Резервная копия

Экран «Данные» создаёт версионируемый JSON (`schemaVersion = 2`) через системный выбор файла Android. В копию входят:

- виды спорта и спортивные центры;
- связи центров с видами спорта;
- все тренировки и их специализированная статистика;
- разовые планы и правила еженедельного повторения.

Импорт выполняется в режиме объединения: новые центры и тренировки добавляются, идентичные тренировки пропускаются. Текущие данные автоматически не удаляются.

## Сборка

Актуальная проверенная цепочка на 7 августа 2026 года:

- Android Gradle Plugin `9.3.1`;
- Gradle `9.7.0`;
- встроенный в AGP Kotlin + Compose plugin `2.4.10`;
- Compose BOM `2026.06.01`;
- Room `2.8.4`;
- compile SDK `37.1`, target SDK `37`, min SDK `26`;
- JDK `17`.

```powershell
$env:JAVA_HOME='C:\Program Files\Android\Android Studio\jbr'
.\gradlew.bat testDebugUnitTest assembleDebug
.\gradlew.bat connectedDebugAndroidTest
```

Debug APK создаётся в `app/build/outputs/apk/debug/app-debug.apk`.

## Проверки

Unit-тесты покрывают парсинг CSV, обе кодировки, JSON round-trip, справочник сложностей и спортивные агрегаты. Инструментальные тесты на эмуляторе проверяют миграцию Room `1 → 2` и сохранение старых агрегированных данных скалолазания.
