# Sports Activity Assistant

Самостоятельный локальный Android-журнал личных тренировок. **Без Telegram, внешних аккаунтов, сервера, телеметрии и доступа приложения в интернет.** Базовая версия 1.9.2 / код 13; Android 8.0 (API 26) и выше, Room 7, резервные копии JSON 6.

## Возможности

- Универсальная тренировка: дата, вид спорта, спортивный центр; спортивные детали хранятся отдельно.
- Футбол: командный счёт, личные голы/передачи; необязательные дистанция, состав команды и минуты игры.
- Скалолазание: несколько трасс, дисциплина, категория, успех и повторения. Трудность — французская шкала, болдер — Fontainebleau, скорость — стандартная 15 м / иная трасса без категории сложности.
- Ввод, редактирование и подтверждаемое удаление; черновики и повтор записи без дублей.
- Общая/спортивная статистика, фильтр периода/центра, динамика по месяцам, история страницами по 20.
- Справочник центров с доступными видами спорта и архивом без потери истории.
- Календарь результатов/планов: разовые/еженедельные события, перенос/отмена события или серии, связанный результат по плану.
- Системные файловые диалоги: предпросмотр, сопоставление центров/профилей, проверенный чтением локальный бэкап и восстановление без очистки базы.
- Состояния загрузки/ошибки/повтора, альбомная навигация и прокрутка длинных форм с клавиатурой/увеличенным шрифтом.

Первый запуск создаёт профиль и справочники, **не демонстрационные тренировки**. В APK нет сетевых разрешений; автоматический системный бэкап и перенос исключены. Резервируйте историю вручную до удаления приложения/очистки данных.

## Установка и первые действия

1. Соберите debug APK по инструкции ниже: `app/build/outputs/apk/debug/app-debug.apk`.
2. Перенесите APK на Android-устройство и откройте его; Android может запросить разрешение установки из выбранного источника. APK подписан отладочным ключом и предназначен для локальной проверки, не публикации.
3. Создайте место в «Центры». В «Расписание» нажмите «+» → «Записать результат» / «Запланировать».
4. Для истории: «Данные» → «Выбрать файл», проверьте предпросмотр/сопоставления, затем «Применить импорт». Сверьте статистику/календарь.
5. «Сохранить копию в файл»: выберите **локальное** хранилище и дождитесь подтверждения проверки чтением. JSON не зашифрован; облачные пункты диалога относятся к сторонним приложениям.

[Русское руководство](docs/user-manual.ru.md), [English manual](docs/user-manual.en.md). Интерфейс пока русскоязычный.

Обновление APK выполняйте без удаления приложения/очистки базы. Номер устройства заменить по `adb devices`:

```powershell
$taskAdb='C:\Users\PAVEL\AppData\Local\Android\Sdk\platform-tools\adb.exe'
& $taskAdb devices -l
& $taskAdb -s emulator-5556 install -r app/build/outputs/apk/debug/app-debug.apk
& $taskAdb -s emulator-5556 shell am start -n com.pamurlykin.sportsactivityassistant/.MainActivity
```

Сначала сохраните проверенный JSON. Обновление требует совместимого ключа подписи; debug-ключ другой машины может отличаться. При `INSTALL_FAILED_UPDATE_INCOMPATIBLE` не удаляйте единственную историю: экспортируйте из прежней версии и проверьте файл перед отдельной установкой/восстановлением. Новую копию старое приложение может не принять. Release APK **неподписанный**, без ключа распространения и публикации.

## Сборка на Windows

Проверенная конфигурация: Android Studio JBR 25.0.3, Java source/target 17, compile platform 37.1; min 26 / target 37. Совместимый закреплённый набор проверен по первичным источникам **7 октября 2026 года**: AGP 9.4.1, Gradle 9.8.0, Compose/Serialization plugins 2.4.20, KSP 2.3.12, Compose BOM 2026.09.00, Room 2.8.5. [Источники и совместимость](docs/stage-02-toolchain.md). Версии — `gradle/libs.versions.toml`, Wrapper имеет SHA256.

Откройте проект в Android Studio, установите SDK и задайте путь в локальном, **не коммитируемом** `local.properties`, например `sdk.dir=C:/Users/PAVEL/AppData/Local/Android/Sdk`. Настройте JDK:

```powershell
$env:JAVA_HOME='C:\Program Files\Android\Android Studio\jbr'
.\gradlew.bat --version
.\gradlew.bat verifyOfflinePolicy testDebugUnitTest lintDebug assembleDebug assembleRelease
```

Первое наполнение кэша требует сети **только на компьютере разработчика**. Далее добавьте `--offline`; установленному приложению сеть не нужна. Release: `app/build/outputs/apk/release/app-release-unsigned.apk`.

## Локальные проверки

Runner устанавливает и удаляет приложение. **Никогда не запускайте его на устройстве с личной историей**: используйте отдельный пустой тестовый AVD. Отключите Wi-Fi/мобильные данные и проверьте системные настройки; одного флага авиарежима недостаточно. Безопасная обёртка отказывается использовать физическое устройство/установленный пакет и проверяет свежий XML:

```powershell
.\scripts\run-local-checks.ps1 -Serial emulator-5556 -SdkPath 'C:\Users\PAVEL\AppData\Local\Android\Sdk' -ExpectedAndroidTests 123
```

Выполняются офлайн-политика, JVM-тесты, Lint, обе сборки и `connectedDebugAndroidTest`. `BUILD SUCCESSFUL` сам по себе не доказывает запуск тестов. Отчёты — `app/build/test-results/testDebugUnitTest`, `app/build/outputs/androidTest-results/connected/debug`, `app/build/reports/lint-results-debug.txt`.

[Этап 11](docs/stage-11-local-testing.md): 63 JVM и по 122 Android-теста на API 26/37, обновление без очистки данных, системные файлы и 2000 тренировок / 10000 трасс за 10 лет. Этап 12 добавил 3 теста реестра и 1 Android-тест **самих файлов документации**: итоговые 66 JVM и по 123 Android-теста на двух API прошли без ошибок/пропусков, Lint без замечаний. Матрица, команды и SHA256 APK — в [итоговой приёмке](docs/stage-12-acceptance.md).

CI `.github/workflows/android.yml` проверяет манифесты, JVM, Lint и APK, действия закреплены SHA. Android-тесты выполняются локально отдельно; push не означает проверенный успешный удалённый CI.

## Форматы истории и копии

- JSON 1–6, строгий UTF-8. JSON 6: UUID/время создания, профили, центры/архив/спорты, результаты/трассы, планы/серии/исключения/ссылки, избранное и сопоставления.
- Футбольный CSV: UTF-8/BOM или Windows-1251, `;`/`,`, кавычки; обязательные `user_id`, `training_date`, `sports_complex_id`, `team_goals_scored`, `team_goals_conceded`, `user_goals_scored`, `user_assists`. Дистанция/игроки/время необязательны. Номер центра — подсказка, не локальный ID; `user_id` — поле файла, не аккаунт.
- Лимиты: 16 МиБ / 100000 объектов. До подтверждения база неизменна, применение транзакционное. UUID пропускается, конфликт требует сохранить локальную запись; одинаковые реальные тренировки с разными UUID не объединяются автоматически.
- Старые файлы получают идентичность по точным байтам/позиции: изменение файла меняет источник. Неизвестный формат не угадывается, повреждённый файл не очищает базу.

[Обезличенные примеры с контрольными результатами](docs/examples/README.md), [контракт JSON/CSV](docs/backup-format.md), [источники шкал](docs/climbing-grades.md). Примеры не входят в APK и не импортируются автоматически.

## Архитектура и расширение

`trainings` хранит универсальные атрибуты, футбол — `football_trainings`, скалолазание — `climbing_trainings` / `climbing_routes`. Родитель и детали записываются атомарно. Room 7, миграции 1 → 7 без destructive fallback, схемы 2–7 в `app/schemas`.

Compose UI → lifecycle-aware `MainViewModel` → `AppRepository` → Room DAO. Спортивный реестр выбирает валидатор/кодек/дочернюю запись/агрегаты; `SportEditors` выбирает типизированную saveable-форму. Общие календарь/статистика не должны знать поля следующего спорта.

[Добавление спорта](docs/sport-modules.md) требует DTO, дочерней таблицы/миграции, версии бэкапа, модуля/редактора и тестов. Третья тестовая реализация проверяет контракт, **не является готовым спортом** и отсутствует в APK. Рабочий реестр — только футбол/скалолазание.
