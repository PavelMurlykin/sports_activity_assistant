# Sports Activity Assistant

Самостоятельное локальное Android-приложение на Kotlin и Jetpack Compose для учёта личных тренировок. Интернет, внешние аккаунты и сервер не нужны. Данные хранятся на устройстве; импорт и резервное копирование выполняются по выбору пользователя через файлы.

## Возможности

- универсальная запись тренировки: дата, вид спорта и спортивный центр;
- отдельная статистика каждого вида спорта;
- футбол: счёт, личные голы и передачи, необязательные дистанция, число игроков в команде и длительность;
- скалолазание: несколько трасс за тренировку, дисциплины «Трудность», «Скорость» и «Боулдеринг», французская шкала сложности от `3` до `9C`, признак успешного прохождения каждой трассы;
- общая статистика, группировка по месяцам и детальные агрегаты по спорту;
- календарь состоявшихся, разовых будущих и еженедельных тренировок;
- редактируемый справочник спортивных центров и доступных в них видов спорта;
- импорт футбольной истории из CSV;
- локальный экспорт и повторный импорт резервной копии JSON;
- защита от повторного импорта одинаковых тренировок.

При первом запуске создаются только справочники и локальный профиль; демонстрационные тренировки используются исключительно в тестах и не попадают в пользовательскую статистику.

В установленном APK нет сетевых разрешений. Автоматический системный бэкап отключён; правила Android исключают данные из облачного бэкапа и автоматического переноса между устройствами. Для резервирования используйте ручной экспорт JSON перед удалением приложения или очисткой его данных.

Базовая таблица `trainings` не содержит специфичных для спорта полей. Футбольные данные лежат в `football_trainings`, скалолазные — в `climbing_trainings` и `climbing_routes`. Поэтому новый вид спорта добавляется отдельной дочерней сущностью, формой и расчётом статистики без изменения общих атрибутов календаря.

## Импорт футбольной истории из CSV

Приложение принимает UTF-8/UTF-8 BOM и Windows-1251, разделители `;` и `,`. Поддерживаемый заголовок:

```csv
user_id;training_date;sports_complex_id;team_goals_scored;team_goals_conceded;user_goals_scored;user_assists;distance_km
1;2025-12-14;2;5;3;2;1;7,35
1;2025-12-21;2;1;1;0;1;
```

`sports_complex_id` должен существовать в справочнике приложения: `1` — «Энергия Высоты», `2` — «Фабрика Футбола», `3` — «Арена на горе» в начальном справочнике. Поле `user_id` — идентификатор источника в старом формате файла, а не внешний аккаунт; записи импортируются в единственный локальный профиль. Пока нет предварительного просмотра или выбора пользователя: не импортируйте файлы с данными нескольких людей. Совпадающие по содержанию записи пропускаются, поэтому две реальные одинаковые тренировки могут быть приняты за одну.

## Резервная копия

Экран «Данные» создаёт версионируемый JSON (`schemaVersion = 2`) через системный выбор файла Android. В копию входят:

- виды спорта и спортивные центры;
- связи центров с видами спорта;
- все тренировки и их специализированная статистика;
- разовые планы и правила еженедельного повторения.

Импорт выполняется в режиме объединения: новые центры и тренировки добавляются, идентичные тренировки пропускаются. Текущие данные автоматически не удаляются.

Текущий формат не сохраняет связь отдельного плана с правилом повторения и не обеспечивает восстановление всех возможных связей. До завершения этапа безопасного обмена сохраняйте исходные файлы и проверяйте восстановленную историю. JSON не зашифрован. Выбирайте локальное хранилище в системном диалоге: доступные в нём облачные провайдеры принадлежат другим приложениям, а не этому приложению.

## Сборка

Стабильные версии, проверенные по первичным источникам 7 октября 2026 года (подробности в отчёте этапа 2):

- Android Gradle Plugin `9.4.1`;
- Gradle `9.8.0`;
- встроенный в AGP Kotlin + Compose/Serialization plugins `2.4.20`, KSP `2.3.12`;
- Compose BOM `2026.09.00`;
- Room `2.8.5`;
- compile SDK `37.1`, target SDK `37`, min SDK `26`;
- Java source/target `17`; фактический JDK локального прогона указан в отчёте этапа.

```powershell
$env:JAVA_HOME='C:\Program Files\Android\Android Studio\jbr'
.\gradlew.bat verifyOfflinePolicy testDebugUnitTest lintDebug assembleDebug
.\gradlew.bat connectedDebugAndroidTest
```

Debug APK создаётся в `app/build/outputs/apk/debug/app-debug.apk`.

## Проверки

Unit-тесты покрывают парсинг CSV, обе кодировки, JSON round-trip, справочник сложностей и спортивные агрегаты. Инструментальные тесты на эмуляторе проверяют миграцию Room `1 → 2` и сохранение старых агрегированных данных скалолазания.

На этапе 1 добавлены инструментальные проверки офлайн-политики установленного APK и контрольного набора статистики/календаря. Свежий прогон: 10 модульных и 7 Android-тестов, Lint без замечаний; запуск на эмуляторе с отключённой сетью успешен. Подробности и ограничения — в отчёте этапа.

Сборка из пустого кэша требует загрузки инструментов и библиотек. После загрузки повторные сборки можно выполнять с `--offline`. Работа установленного приложения не требует сети.

`verifyOfflinePolicy` проверяет объединённые манифесты обеих сборок на отсутствие сетевых разрешений и отключение системного бэкапа. `.github/workflows/android.yml` запускает эту проверку, модульные тесты, Lint и сборки debug/release; действия закреплены полными SHA. `assembleRelease` пока создаёт неподписанный APK, без публикации. Все версии библиотек находятся в `gradle/libs.versions.toml`.
